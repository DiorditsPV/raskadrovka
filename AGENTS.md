# Работа с репозиторием

Правила для агента после клонирования. Скрипты, которых пока нет, помечены фазой
[плана ребилда](docs/superpowers/plans/2026-09-07-rebuild.md); до их появления шаг делается вручную
по описанному контракту.

## Устройство

- Одна книга — папка `books/<книга>/` с `book.json` и `bible.json`. Одна партия сцен — папка
  `books/<книга>/<партия>/` с `scenes/`, `prompt/`, `input/`, `metadata/` и README. Готовые
  изображения лежат в едином корневом `output/` без подпапок, имя
  `<книга>--<партия>--<сцена>.png`.
- Текст книги в git не попадает. Файл книги — в `books/<книга>/source/`, разбор на абзацы — в
  `cache/`; обе папки игнорируются. Проверять `git status` перед коммитом: текстовых файлов книги
  в индексе быть не должно.
- В `output/` хранится одна актуальная версия каждой сцены. При замене прежний результат и его
  партия переезжают в локальный игнорируемый `archive/`; входы, на которые ссылаются другие партии,
  не удалять. Флаг `latest` в `metadata/request.json` отмечает актуальные версии.
- Манифест партии имеет `schema_version: 2`, пути относительно папки партии, SHA-256 карточки,
  промпта, входов и результата. Образец — в `books/README.md`.
- После любых изменений запускать `python3 scripts/build_gallery.py`. Он проверяет хеши и ссылки
  и пересобирает `index.html`. Проверка прав `scripts/check_rights.py` появится в фазе 2 и будет
  вызываться из той же сборки.

## Раскладка на сцены

- Сначала `book.json` и кандидаты: `scripts/ingest_book.py` (фаза 3) и `scripts/scene_candidates.py`
  (фаза 4). Читать целиком книгу не нужно: агент смотрит кандидатов и их окрестности в пределах
  главы.
- Сцена — один момент, который можно нарисовать: место, время и свет, кто в кадре и что делает,
  настроение, ключевые предметы. Растянутое во времени действие и внутренний монолог — не сцена.
- Карточка сцены — `scenes/<сцена>.json` по контракту из `books/README.md`. Локатор (глава и
  диапазон абзацев) обязателен. Отрывок — не длиннее двух абзацев и только из указанных абзацев;
  для книг со статусом `protected` это проверяется, для `public-domain` ограничение снято.
- Персонажи в карточке ссылаются на `bible.json`. Новый герой или место сначала заводится в
  библии с локатором на описание в тексте, потом используется в сцене.

## Промпт и референсы

- Промпт собирается скриптом `scripts/build_prompt.py` (фаза 7) из карточки, библии и
  `metadata/refs.json`. До его появления писать промпт вручную по шаблону из спецификации, чтобы
  потом сборка воспроизвела его без правок.
- Роли изображений в промпте разделять явно: стилевые референсы задают палитру, рисовку и
  фактуру; их сюжеты, здания, лица и надписи не переносить. Содержание кадра задаёт карточка.
- Внешность героев описывать только словами книги через библию. Не ссылаться на экранизации,
  актёров и иллюстрации других художников; не называть живых художников.
- Каждый референс в `input/` имеет запись в `metadata/refs.json`: источник, автор, лицензия.
  Референс без свободной лицензии в git не попадает: он лежит в `refs-local/`, а в манифесте
  помечен `"stored": false` с хешем.
- Генерировать встроенным инструментом. Не переходить на отдельный API без просьбы пользователя.
  Один вызов на сцену; повторы — по запросу. Передавать инструменту сами файлы референсов, а не их
  словесное описание.
- Точечные правки делать через edit-target: прежний результат кладётся в `input/<сцена>/` с ролью
  `edit-target`, промпт правки сохраняется как обычный.

## Регистрация результата

- Сохранить PNG в `output/` под правильным именем, скопировать использованные референсы в
  `input/<сцена>/`, записать хеши и роли в `metadata/request.json`, обновить README партии,
  пересобрать галерею. Скрипт `scripts/register_result.py` (фаза 8) делает это одной командой.
- `archive/` — локальная история и резервные копии. В публичный коммит не добавлять.
