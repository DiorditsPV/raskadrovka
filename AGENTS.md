# Работа с репозиторием

Правила для агента после клонирования. Скрипты, которых пока нет, помечены задачей
[плана ребилда](docs/superpowers/plans/2026-09-07-rebuild.md); до их появления шаг делается
вручную по описанному контракту.

## Устройство

- Одна книга — папка `books/<книга>/` с `book.json`, `bible.json` и `characters/`. Одна
  партия сцен — папка `books/<книга>/<партия>/` с `scenes/`, `prompt/`, `input/`,
  `metadata/` и README. Готовые изображения лежат в едином корневом `output/` без подпапок,
  имя `<книга>--<партия>--<сцена>.png`.
- Манеру серии задаёт направление стиля из `styles/<направление>/`. Партия не собирает
  референсы заново: `scripts/add_ref.py` (задача 4) снимает с направления копию в `input/`
  и переносит записи в `metadata/refs.json`.
- Текст книги в git не попадает. Файл книги — в `books/<книга>/source/`, разбор на абзацы —
  в `cache/`; обе папки игнорируются. Проверять `git status` перед коммитом: текстовых
  файлов книги в индексе быть не должно.
- В `output/` одна версия каждой сцены. Исправление, которое нужно сохранить рядом с
  прежним, делается **новой партией** (`02-<что-исправляли>`): прежняя партия целиком —
  манифест и файлы — уезжает в локальный игнорируемый `archive/`, входы, на которые
  ссылаются другие партии, не удаляются. Флага актуальности в манифесте нет: опубликовано
  то, что лежит.
- Манифест партии имеет `schema_version: 2`, пути относительно папки партии, SHA-256
  карточки, промпта, шаблона промпта, входов и результата. Образец — в `books/README.md`.
- После любых изменений запускать `python3 scripts/check.py` (задача 2) и
  `python3 scripts/build_gallery.py`. Первый проверяет права, карточки, библию и хеши и
  ничего не пишет; второй пересобирает `index.html`.

## Раскладка на сцены

- Сначала `book.json` и, для длинных книг, кандидаты: `scripts/ingest_book.py` (задача 6) и
  `scripts/scene_candidates.py` (задача 16). На книге короче примерно 200 тысяч знаков
  читать текст целиком дешевле, чем настраивать эвристики, — кандидаты там не нужны.
- Сцена — один момент, который можно нарисовать: место, время и свет, кто в кадре и что
  делает, настроение, ключевые предметы. Растянутое во времени действие и внутренний
  монолог — не сцена.
- Карточка сцены — `scenes/<сцена>.json` по контракту из `books/README.md`. Локатор (глава и
  диапазон абзацев) обязателен. Отрывок — целые абзацы локатора, не длиннее двух, и только
  из указанных абзацев; для книг со статусом `protected` это проверяется по
  `paragraph_sha256`, для `public-domain` пределы сняты.
- Персонажи в карточке ссылаются на `bible.json`. Новый герой или место сначала заводится в
  библии с локатором на описание в тексте, потом используется в сцене.

## Библия и листы персонажей

- Библия собирается один раз на книгу: внешность героев и вид мест словами книги, с
  локаторами на описание в тексте. `appearance_en` — не длиннее 300 знаков.
- На каждого героя генерируется **лист персонажа** — одно изображение по описанию из библии
  и выбранному направлению стиля. Он лежит в `books/<книга>/characters/<ключ>.png`, общий
  для всех сцен этой книги, и записывается в библию полями `sheet`, `sheet_sha256`,
  `sheet_prompt`.
- В каждую сцену, где герой в кадре, лист подаётся отдельным входным изображением с ролью
  `character-reference`. Описание словами героя не удерживает: инварианты из библии
  остаются в промпте, но опорой служит лист.

## Промпт и референсы

- Промпт собирается скриптом `scripts/build_prompt.py` (задача 9) из карточки, библии,
  листов персонажей и `metadata/refs.json`. До его появления писать промпт вручную по
  шаблону из спецификации, чтобы потом сборка воспроизвела его без правок.
- Роли изображений в промпте разделять явно: стилевые референсы задают палитру, рисовку и
  фактуру, их сюжеты, здания, лица и надписи не переносятся; лист персонажа задаёт лицо,
  сложение и одежду, его фон и поза игнорируются; содержание кадра задаёт карточка.
- Порядок изображений: стилевые референсы, затем листы персонажей в порядке
  `frame.characters`, затем `edit-target`.
- Внешность героев описывать только словами книги через библию. Не ссылаться на
  экранизации, актёров и иллюстрации других художников; не называть живых художников.
- Каждый референс в `input/` имеет запись в `metadata/refs.json`: источник, автор, лицензия
  и `license_basis` — обоснование свободы и в России, и в США. Референс без свободной
  лицензии в git не попадает: он лежит в `refs-local/`, а в манифесте помечен
  `"stored": false` с хешем и путём в `refs-local/`.
- Генерировать встроенным инструментом. Не переходить на отдельный API без просьбы
  пользователя. Один вызов на сцену; повторы — по запросу. Передавать инструменту сами
  файлы референсов и листов, а не их словесное описание.
- Точечные правки делать через edit-target: прежний результат кладётся в `input/<сцена>/` с
  ролью `edit-target`, промпт правки сохраняется как обычный.

## Регистрация результата

- Сохранить PNG в `output/` под правильным именем, записать хеши и роли в
  `metadata/request.json`, обновить README партии, пересобрать галерею. Скрипт
  `scripts/register_result.py` (задача 10) делает это одной командой.
- `archive/` — локальная история и резервные копии. В публичный коммит не добавлять.
