# Раскадровка — замысел и контракты

Дата: 2026-09-07. Статус: принято в чате, уточнено по опроснику «Развилки ребилда»
(20 решений, 2026-09-07), реализуется по [плану ребилда](../plans/2026-09-07-rebuild.md).

## Цель

Из книги получить серию иллюстраций к её ключевым сценам в одной манере, заданной
стилевым направлением, с полной историей каждой картинки: сцена, промпт, референсы,
результат. Книга в репозиторий не попадает; всё, что попадает, можно публиковать.

## Принципы

- **Сначала картинка, потом машинерия.** Пайплайн проверяется вертикальным срезом на
  двух-трёх сценах, собранных руками, и только потом автоматизируется. Скрипт, не
  прошедший через живой кадр, не пишется.
- **Дёшево.** Книгу целиком дорогой моделью не читают — на длинных книгах скрипт
  отбирает кандидатов эвристиками, и агент смотрит только их окрестности. Для книг
  короче примерно 200 тысяч знаков дешевле прочитать всё, и эвристики не нужны.
- **Без текста книги.** В git — манифест книги, библия, карточки сцен с отрывком не
  длиннее двух абзацев, промпты и записи о референсах. Файл книги и разбор на абзацы
  живут в игнорируемых папках.
- **Стиль — из каталога направлений, эталоны генерируются.** Манера серии не изобретается
  на каждую партию и не выискивается в чужих работах: она берётся из `styles/<направление>/`,
  где манера сначала сформулирована словами в `style_notes_en`, а потом закреплена
  собственными сгенерированными эталонами. Текст первичен, картинка его закрепляет. Партия
  хранит снимок использованных файлов.
- **Герой держится картинкой, а не описанием.** На каждого героя один раз генерируется
  лист персонажа; он подаётся в каждую сцену книги как входное изображение с ролью
  `character-reference`. Текстовые инварианты из библии остаются, но опорой служит лист.
- **Детерминированный промпт.** Промпт собирается скриптом из карточки, библии, листов
  персонажей и записей о референсах и коммитится целиком. Манифест хранит хеш шаблона,
  которым промпт собран, поэтому правка шаблона не переписывает историю.
- **Provenance как в «Окрестностях».** Партия сцен — папка с `input/ prompt/ scenes/
  metadata/`, манифест с SHA-256 всех файлов, плоский `output/`.
- **Только стандартная библиотека.** Скрипты работают на чистом Python 3.10 без
  установки; pytest нужен только тестам.

## Пайплайн

1. `ingest_book.py`: FB2, EPUB, TXT → `book.json` (без текста, с хешами абзацев) +
   `cache/<книга>/paragraphs.jsonl`.
2. Агент: библия `bible.json`, листы персонажей `characters/<ключ>.png`, карточки
   `scenes/<сцена>.json`. На длинных книгах кандидатов подсказывает
   `scene_candidates.py`.
3. `add_ref.py`: направление из `styles/` → снимок в `input/` партии и записи в
   `metadata/refs.json` с хешами и лицензиями.
4. `build_prompt.py`: карточка + библия + листы + `refs.json` → `prompt/<сцена>.txt`.
5. Агент: генерация встроенным инструментом, один вызов на сцену, правки через
   edit-target.
6. `register_result.py`: PNG в `output/`, хеши и роли в `request.json`, README партии.
7. `check.py`: права, карточки, библия, хеши, промпты. `build_gallery.py`: `index.html`.

## Контракты данных

Полные образцы — в [books/README.md](../../../books/README.md) и
[styles/README.md](../../../styles/README.md). Ключевые решения:

- `book.json`: `slug`, `title`, `author`, `translator`, `language`, `edition`,
  `year_published`, `rights{status, basis, checked}`, `source{format, sha256, chars,
  paragraphs}`, `paragraph_sha256[]`, `chapters[{index, title, paragraphs:[start, end)}]`.
  Индексы абзацев стабильны при том же `source.sha256`. `paragraph_sha256[i]` — SHA-256
  нормализованного абзаца `i`; хеши текст не восстанавливают, но позволяют проверить
  отрывок карточки на любой копии репозитория, где кеша нет.
- `bible.json`: `characters{key: {name, appearance, appearance_en, locators[], sheet,
  sheet_sha256, sheet_prompt}}`, `places{key: {name, look_en, locators[]}}`. Русские поля —
  людям, `_en` — промпту. `sheet` — путь к листу персонажа
  `characters/<key>.png` относительно папки книги; лист общий для всех сцен этой книги.
- Карточка сцены: `id`, `book`, `title`, `order`, `locator{chapter, paragraphs:[a, b]}`,
  `excerpt{text, attribution}`, `caption`, `brief` (по-русски), `frame` (по-английски:
  `setting`, `time`, `characters[{ref, state}]`, `action`, `mood`, `details[]`,
  `composition`, `avoid[]`), `style_refs[]`, `invariants[]`. Отрывок — целые абзацы
  локатора после нормализации пробелов, без цитат из середины абзаца.
- `styles/<направление>/style.json`: `slug`, `name`, `about` (по-русски), `style_notes_en`,
  `fits[]` (жанры и эпохи, которым направление идёт), `refs{ref-id: {file, stored, sha256,
  source, author, license, license_basis, why}}`. Эталоны — собственные генерации
  (`own-work`/`generated-here`), от одного до пяти на направление.
- `metadata/refs.json` партии: `{ref-id: {file, stored, sha256, source, author, license,
  license_basis, why, style_notes_en, from_style}}`. `file` — путь относительно папки
  партии: общий для серии стилевой референс лежит в `input/` без подпапки, потому что
  партия по определению делит одну манеру; в `input/<сцена>/` попадает только
  принадлежащее кадру — `edit-target`. Для `stored: false` в `file` пишется путь в
  локальную `refs-local/<имя>`.
- `metadata/request.json`: `schema_version: 2`, `book`, `title`, `request`, `style`,
  `path_base`, `scenes[{id, title, order, caption, card, card_sha256, prompt,
  prompt_sha256, template_sha256, output, output_sha256, inputs[{path, sha256, role,
  stored}]}]`. Роли входов: `style-reference`, `character-reference`, `edit-target`.
  Флага `latest` нет — см. «Версии результатов». Схема остаётся второй: манифестов по
  первой схеме не существует, мигрировать нечего.

## Версии результатов

Одна сцена — один актуальный PNG в плоском `output/`. Исправление сцены делается **новой
партией**: прежняя запись уходит из манифеста вместе с файлами в локальный игнорируемый
`archive/`, новая партия получает свой слаг (`02-<что-исправляли>`) и своё имя результата.
Так уже устроены «Окрестности». Поэтому в манифесте нет флага `latest`, а в галерее нет
блока прежних версий: публикуется только актуальное, история живёт локально и в git-логе.

## Шаблон промпта

По-английски, секциями: Use case · Asset · Input images (роль каждого изображения;
стилевой референс отдаёт палитру, рисовку и фактуру, его сюжеты, фигуры и надписи не
переносятся; лист персонажа отдаёт лицо и фигуру) · Series visual language (из
`style_notes_en`) · Scene · Characters (из библии плюс состояние в кадре) · Action ·
Mood · Details · Composition · Source passage (отрывок дословно, как контекст, не для
отрисовки текста) · Identity invariants (записи библии из `invariants`) · Avoid (из
карточки плюс постоянные: образы экранизаций, чужие иллюстрации, подписи, водяные знаки,
читаемый текст) · Final constraints.

Порядок изображений: стилевые референсы, затем листы персонажей в порядке
`frame.characters`, затем `edit-target`, если есть.

Шаблон живёт в `scripts/templates/prompt.txt`. Его SHA-256 пишется в запись сцены как
`template_sha256`; сборка сверяет промпт байт-в-байт только для сцен, чей
`template_sha256` совпадает с текущим шаблоном. Сцены, собранные прежним шаблоном, — это
исторические записи: их промпт остаётся тем, из которого получена картинка.

## Права

Политика — в [RIGHTS.md](../../../RIGHTS.md). Проверяемые пределы для книг со статусом
`protected`: отрывок не длиннее двух абзацев и 1500 знаков, сумма отрывков не больше 3%
объёма книги, отрывок совпадает с целыми абзацами локатора. Совпадение проверяется по
`paragraph_sha256` из `book.json`, поэтому работает и там, где нет кеша. В `input/` нет
текстовых файлов больше 4 КБ; под `books/` нет файлов книг вне игнорируемой `source/`.
Референс попадает в git только со свободной лицензией, записью об источнике и
`license_basis` — обоснованием свободы и в России, и в США.

## Родство с «Окрестностями»

Покрытие идеи родительским проектом на момент старта — около 40%.

| Слой                                | Покрытие | Что взято                                                                      |
|-------------------------------------|----------|--------------------------------------------------------------------------------|
| Приём книги и раскладка на сцены    | 0%       | ничего; вход там — бриф человека                                               |
| Отбор сцен и библия персонажей      | 10%      | паттерн identity invariants и один главный стилевой референс                   |
| Стилевые референсы и шаблон промпта | 80%      | роли изображений, запрет копировать содержимое референса, секции промпта       |
| Генерация и цикл правок             | 90%      | встроенный инструмент, один вызов на сюжет, edit-target                        |
| Хранение и provenance               | 90%      | устройство партии, манифест с SHA-256, плоский `output/`                       |
| Галерея с проверками                | 60%      | скрипт целиком; группы теперь из `book.json`, порядок сцен и подпись добавлены |
| Права и публикация                  | 50%      | схема лицензий и записи об источниках; политика по тексту новая                |

## Не делаем

Отдельный API генерации (генерация идёт встроенным инструментом агента), веб-интерфейс,
базу данных, полнотекстовый поиск, автоматический подбор референсов в интернете, перевод
карточек, CI. Появится по явной просьбе.

## Гейты

- После каждой задачи: `pytest tests/` и `python3 scripts/check.py`.
- Перед публикацией первой книги: проверка без ошибок, скриншоты галереи, README с
  примерами.
